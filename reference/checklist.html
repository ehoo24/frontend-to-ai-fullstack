生产上线前检查清单与排错速查 (Checklist)

在将任何全栈 AI 应用发布至测试环境或正式生产环境前，必须逐项核对以下四类关键指标。

一、数据与服务工程门禁

  • 数据库索引检查：所有高频 WHERE 条件字段、外键、排序字段以及向量字段是否均建立了恰当索引（B-Tree 或 pgvector HNSW 索引）？
  • 数据库连接池：ORM 连接池上限是否根据容器规格设置（如 max: 20），连接泄漏超时（idleTimeoutMillis）是否配置？
  • 事务锁安全：涉及账户扣款、Token 扣减等写操作，是否使用了 SELECT ... FOR UPDATE 悲观锁或乐观锁防并发超卖？
  • 请求超时与熔断：所有对外部上游（OpenAI、第三方微服务）的 HTTP 调用是否均显式配置了连接超时（timeout: 10000）？
  • 接口幂等保护：核心写入接口是否支持 Idempotency-Key 请求头并在 Redis 中做了状态防重？
  • 优雅停机 (Graceful Shutdown)：Node.js 进程在收到 SIGTERM 信号时，是否会等待未完成的长连接并在 10 秒内优雅关闭数据库连接池？

二、安全与权限防御门禁

  • 敏感密钥隔离：前端生产代码 bundle 中是否 100% 杜绝了 OPENAI_API_KEY 等敏感环境变量？
  • 服务端强制鉴权：每个受保护的 API 接口是否在服务端拦截器中验证了 JWT 有效性，而不是只靠前端隐藏操作按钮？
  • 多租户越权防护：所有数据库查询与向量检索 SQL 中，是否均强制绑定了当前登录用户的 tenant_id，防止越权拉取其他租户知识库？
  • Prompt 注入预过滤：是否针对用户输入做了敏感指令（如 ignore previous instructions、system prompt）的正则特征扫描与风险阻断？
  • Agent 工具权限白名单：破坏性操作（删除、退款、修改全局配置）是否默认禁止 AI 自动执行，必须走人工审核（Human-in-the-Loop）？

三、AI 质量与成本监控门禁

  • SSE 请求中断释放：客户端点击“停止生成”或关闭网页时，服务端是否监听到连接关闭并立即调用 AbortController.abort() 掐断模型推理？
  • Token 预算与单次硬上限：模型请求是否设置了严格的 max_tokens，防止死循环或恶意输入耗尽账户余额？
  • 黄金测试集回归：最近一次代码或 Prompt 变更后，是否在至少 30 组标注问答样本上运行了自动化评测，Faithfulness 得分是否 >= 0.85？
  • 优雅拒答机制：当检索到的上下文片段与用户提问无关时，模型是否能礼貌且明确地拒答，而不是一本正经地编造假答案？
  • 来源溯源高亮：最终输出结果中是否附带真实的知识库文档名称与切片序号，前端能否点击定位到引用来源？

四、生产运维与可观测性门禁

  • 健康检查端点：服务端是否提供了 /healthz 接口，能够探测进程存活以及数据库/Redis 的连通性？
  • 结构化日志：线上日志是否统一为 JSON 格式，且每次请求包含全局唯一的 trace_id？
  • 容器非 Root 运行：Dockerfile 中是否配置了 USER node 运行应用，杜绝容器越权逃逸风险？
  • 数据库可回滚演练：本次版本引入的数据库表结构变更，是否事先在预发环境演练过一键 down 回滚并验证数据完好？
  • 异常指标告警：Sentry 或 APM 平台是否配置了阈值告警（如：HTTP 5xx 突增、Token 消耗速率突增、平均延迟超过 5 秒）？
